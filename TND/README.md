# TheNotDivision (TND) — MVP 0.1

Первая тестовая версия сервиса совместного просмотра.

## Что уже работает

- создание комнаты и вход по шестизначному коду;
- до 12 участников в одной комнате;
- общий чат и быстрые реакции;
- добавление видео в очередь и голосование за ролики;
- синхронное состояние плеера;
- голосование за воспроизведение, паузу и перемотку;
- голосовой чат через WebRTC (микрофон включается только после нажатия кнопки и выдачи разрешения браузера).

## Поддерживаемые источники видео в MVP

1. Прямые ссылки на видеофайлы, например `.mp4` или `.webm`, если сервер источника разрешает воспроизведение в браузере (CORS/формат/кодек могут влиять на результат).
2. Публичные видео YouTube через официальный встроенный плеер.

Ссылки на страницы Netflix, Disney+, другие защищённые стриминговые платформы и DRM-контент не будут воспроизводиться внутри этого плеера. MVP не обходит DRM и ограничения сторонних сервисов.

## Запуск на Windows 10/11

1. Установи Python 3.11 или новее с сайта https://www.python.org/downloads/ . При установке включи опцию **Add Python to PATH**.
2. Распакуй архив в удобную папку, например `C:\TND`.
3. Открой папку и дважды нажми `run_windows.bat`.
4. При первом запуске скрипт создаст виртуальное окружение и установит зависимости.
5. Открой в браузере http://127.0.0.1:8000 .
6. Создай комнату. Друг на том же компьютере может подключиться по коду; для друга через интернет потребуется развернуть сервер на хостинге с HTTPS/WSS.

## Запуск вручную

```bash
python -m venv .venv
# Windows PowerShell:
.venv\\Scripts\\Activate.ps1
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn server:app --host 127.0.0.1 --port 8000 --reload
```

Затем открой http://127.0.0.1:8000 .

## Как проверить вдвоём

1. Открой сайт в первом окне браузера, введи имя и нажми «Создать пати».
2. Открой сайт во втором окне (можно в режиме инкогнито), введи другое имя и код комнаты.
3. Добавь ссылку на публичное видео YouTube или прямую ссылку на MP4/WebM.
4. Добавь ещё один ролик в очередь. Участники могут голосовать за него.
5. Нажми Play/Pause или перемотку: действие применится после большинства голосов.
6. Нажми «Включить микрофон» и разреши доступ к микрофону, чтобы протестировать голосовой чат.

## Важные ограничения этой версии

- Комнаты, очередь и чат хранятся в памяти сервера. После перезапуска сервера они исчезнут.
- Сервер ограничивает комнату 12 участниками. Для реального голосового общения лучше начать с 2–4 участников: WebRTC mesh создаёт отдельное соединение между каждой парой.
- Для интернета нужен публичный сервер с HTTPS. Браузеры обычно требуют безопасное соединение для доступа к микрофону (исключение — localhost).
- Для голосового чата может понадобиться TURN-сервер, если участники находятся за сетями, которые не пропускают прямое WebRTC-соединение. В MVP указан публичный STUN для тестов.
- Автовоспроизведение может блокироваться браузером. Участнику иногда нужно один раз нажать кнопку воспроизведения в своём окне.
- Это MVP, а не готовый публичный сервис: перед реальным запуском нужны авторизация, защита от спама, лимиты, постоянная БД, HTTPS, логирование и политика конфиденциальности.

# Публикация в интернете: Netlify + Render

В этой схеме Netlify раздаёт интерфейс, а Render запускает Python/FastAPI и WebSocket. Загружать проект нужно в GitHub, а затем подключить один репозиторий к обоим сервисам.

## 1. Подготовь GitHub-репозиторий

1. Создай новый репозиторий на https://github.com/new (например, `TheNotDivision`).
2. Распакуй архив и открой папку `TND`.
3. Загрузи **содержимое папки `TND`** в корень репозитория. В корне GitHub должны лежать `server.py`, `requirements.txt`, `render.yaml`, `netlify.toml` и папка `static`.
4. Не загружай `.venv`, пароли или приватные ключи. В проекте нет необходимости добавлять секреты для этого MVP.

## 2. Сначала разверни сервер на Render

1. Открой https://render.com/ и войди через GitHub.
2. Выбери **New → Blueprint** (если Render предлагает использовать Blueprint) и подключи репозиторий `TheNotDivision`. Render прочитает `render.yaml` и создаст веб-сервис `tnd-api`.
3. Если Blueprint недоступен, выбери **New → Web Service** и задай:
   - Root Directory: оставить пустым;
   - Runtime: Python 3;
   - Build Command: `pip install -r requirements.txt`;
   - Start Command: `uvicorn server:app --host 0.0.0.0 --port $PORT`.
4. Дождись статуса **Live** и скопируй адрес сервиса, например `https://tnd-api.onrender.com`.
5. Проверь адрес в браузере, добавив `/health`. Должен появиться JSON со статусом `ok`.

## 3. Подключи сайт на Netlify

1. Открой https://app.netlify.com/ и войди через GitHub.
2. Выбери **Add new site → Import an existing project** и подключи тот же репозиторий.
3. В настройках сборки укажи:
   - Base directory: пусто;
   - Build command: пусто;
   - Publish directory: `static`.
4. Нажми Deploy. Netlify выдаст адрес вида `https://название-сайта.netlify.app`.

## 4. Свяжи Netlify с Render

1. В GitHub открой `static/config.js` и замени пустой адрес на адрес Render:

   ```js
   window.TND_API_BASE = "https://tnd-api.onrender.com";
   ```

   Вставь свой реальный адрес Render, без `/` в конце. Сохрани изменение (Commit changes). Netlify автоматически пересоберёт сайт.

2. В Render открой сервис `tnd-api` → **Environment** и измени переменную `FRONTEND_ORIGINS` с `*` на точный адрес Netlify, например:

   ```text
   https://название-сайта.netlify.app
   ```

   Если у сайта есть несколько доменов (например, `www` или собственный домен), перечисли их через запятую без пробелов. Сохрани изменения и дождись перезапуска сервиса.

3. Открой Netlify-сайт. Создай комнату, затем открой сайт во втором браузере или на другом устройстве и подключись по коду.

## 5. Ограничения бесплатного MVP

- Бесплатный Render может «усыплять» сервис после периода бездействия. Первое подключение после сна может занять некоторое время.
- Данные комнат находятся в оперативной памяти. Перезапуск или сон/перезапуск сервера может удалить активные комнаты и очередь.
- Не запускай несколько экземпляров сервера: сейчас комнаты и WebSocket-соединения хранятся в памяти одного процесса.
- Голосовой чат использует WebRTC и тестовый STUN. Для надёжной связи между любыми сетями может понадобиться собственный TURN-сервер.
- Перед публичным запуском нужны постоянная БД, авторизация, защита от спама и злоупотреблений, лимиты, мониторинг и правила конфиденциальности.

## Если сайт не подключается

1. Проверь, что `https://ТВОЙ-RENDER-АДРЕС/health` отвечает `{"status":"ok", ...}`.
2. Проверь `static/config.js`: адрес должен начинаться с `https://`, не содержать `/ws` и не иметь `/` в конце.
3. Проверь `FRONTEND_ORIGINS` в Render: там должен быть точный домен Netlify, включая `https://`.
4. После изменения `config.js` дождись нового Deploy на Netlify; после изменения переменной Render дождись перезапуска сервиса.
5. Открой инструменты разработчика браузера (F12 → Console) и посмотри сообщение об ошибке подключения.
